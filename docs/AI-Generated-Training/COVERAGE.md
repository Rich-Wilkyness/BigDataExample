## Status vocabulary

| Status | Meaning |
| --- | --- |
| Planned | Scope exists, but the guide or artifact has not been authored |
| Documentation complete | Guide meets the topic template; executable evidence may still be absent |
| Partial | Some required guide, example, test, or evidence is incomplete |
| Locally verified | Behavior ran against a bounded local fixture or process |
| Integration verified | Behavior ran against the named real engine or service |
| Distributed verified | Behavior ran across multiple relevant workers or nodes with observed failure behavior |
| Production evidence | Observed workload and operational evidence exists in an authorized production environment |
| Complete | The documented topic contract and all currently required evidence are satisfied |

## Scope boundaries

- Python and SQL are foundational; Scala, Java, R, and vendor languages are
  comparisons or specializations unless a later accepted requirement changes scope.
- Hadoop and MapReduce are taught as durable architecture foundations. Installing
  a legacy ecosystem is not a prerequisite for understanding it.
- Data science, statistics, machine learning, BI visualization, and application
  development are downstream interfaces. Deep specialization belongs in a
  separate curriculum unless required by a data-engineering contract.
- Cloud providers are implementation variants. Initial guides remain
  vendor-neutral; a later specialization may map the same guarantees to one cloud.
- Products are replaceable examples. No area is complete through product API
  coverage alone.
- Security, privacy, quality, testing, observability, failure recovery, schema
  evolution, performance, and cost begin with the first example and later receive
  dedicated synthesis guides.
