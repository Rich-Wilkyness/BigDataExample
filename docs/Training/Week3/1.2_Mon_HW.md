### 1. Spark Architecture — Verbal

Explain what happens from the time the following command is executed until the Spark application finishes:

```bash
spark-submit --master yarn \
  --deploy-mode cluster \
  --num-executors 8 \
  --executor-cores 4 \
  --executor-memory 6g \
  sales_job.py
```

Your explanation must include:

* Driver
* Cluster manager
* Worker nodes
* Executors
* Partitions
* Jobs, stages, and tasks
* Logical and physical execution plans

NEED TO ORDER THESE STILL:
1. spark-submit reads the configuration and submits the application to YARN.
2. Because this uses cluster mode, YARN launches an Application Master containing the driver.
3. The driver starts the SparkSession/SparkContext and requests eight executors.
4. YARN allocates resources and launches those eight executors across available worker nodes. It is eight executors total, not eight per worker.
5. Each executor receives four cores and a 6 GiB JVM heap. That provides roughly 32 concurrent task slots if all executors are allocated.
6. DataFrame transformations build a logical plan. When an action requires a result, Catalyst analyzes and optimizes that logical plan, and Spark selects a physical plan.
7. The driver divides execution into jobs, stages, and tasks. Shuffle boundaries usually separate stages, and a stage normally has one task per partition.
8. The driver schedules tasks on executor cores. If there are 200 partitions, the tasks run in waves across the approximately 32 slots.
9. Executors process partitions and report status and bounded results to the driver—not to YARN.
10. AQE may use completed query-stage statistics to modify the remaining physical plan. It does not modify the logical plan after every task.
