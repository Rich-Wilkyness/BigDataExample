# Wednesday: Scala Spark DataFrame API

> Status: Draft  
> Level: Beginner  
> Applies to: Scala 2.13.8, Apache Spark SQL 3.5.9, and DataFrame-based batch analysis  
> Example status: Complete reference examples; JDBC, filter, join, aggregate, ordering, and median flow verified locally  
> Last reviewed: 2026-09

## Overview

Scala Spark code uses the same DataFrame model as PySpark, but the syntax and API ownership differ. Methods such as `filter`, `select`, and `orderBy` belong to a DataFrame. Functions such as `col`, `sum`, and `avg` come from `org.apache.spark.sql.functions` and create `Column` expressions that DataFrame methods place into a lazy query plan.

This guide is a practical reference for the operations used most often in local Spark analysis and ETL work. It does not attempt to list every Spark SQL function.

## Learning objectives

After completing this guide, you should be able to:

1. Distinguish DataFrame methods, imported functions, Column methods, and actions.
2. Import the Spark SQL functions needed by a Scala application.
3. Filter, select, derive, join, group, aggregate, order, inspect, and write DataFrames.
4. Explain when a transformation is lazy and when Spark actually executes it.
5. Compare each grouped result with an aggregate calculated across all groups.
6. Avoid common mistakes involving ignored return values, ambiguous columns, nulls, and driver collection.

## 1. The API ownership model

Read a DataFrame expression from left to right:

```scala
factSalesDf.filter(col("quantity") >= 4)
//          ------ --------------------
//          DataFrame       Column
//          method          expression
```

| API owner | Examples | What it normally returns |
| --- | --- | --- |
| `DataFrame` / `Dataset[Row]` | `filter`, `select`, `join`, `groupBy`, `orderBy` | A new lazy DataFrame or a grouped-data builder |
| `org.apache.spark.sql.functions` | `col`, `lit`, `sum`, `avg`, `when`, `trim` | Usually a lazy `Column` expression |
| `Column` | `alias`, `cast`, `desc`, `isNull`, `isin` | Another `Column` expression |
| `RelationalGroupedDataset` | `agg`, `count`, `sum` | A new aggregated DataFrame |
| Action or terminal writer | `show`, `count`, `collect`, `first`, `write...save` | A displayed result, local value, or external output |

This distinction explains why IntelliJ may resolve `filter` without an import but ask you to import `col`.

## 2. Imports

Import only the functions used by the file when you want the origin of each name to remain visible:

```scala
import org.apache.spark.sql.functions.{avg, col, lit, sum, when}
```

Scala 2.13 also supports the wildcard form commonly seen in Spark examples:

```scala
import org.apache.spark.sql.functions._
```

Other common imports belong to different packages:

```scala
import org.apache.spark.sql.{DataFrame, SparkSession}
import org.apache.spark.sql.expressions.Window
import org.apache.spark.sql.types.{DecimalType, IntegerType, StringType}
import org.apache.spark.storage.StorageLevel
```

## 3. DataFrames are immutable and lazy

A transformation returns a new DataFrame. It does not modify the original reference:

```scala
val filteredSales = factSalesDf.filter(col("quantity") >= 4)

// factSalesDf still describes all fact rows.
// filteredSales describes only rows whose quantity is at least four.
```

Prefer `val` and give each meaningful stage a name:

```scala
val validSales = factSalesDf.filter(col("quantity") > 0)
val reportColumns = validSales.select("customer_key", "product_key", "sales_amount")
val orderedReport = reportColumns.orderBy(col("sales_amount").desc)
```

The transformations above build a logical plan. An action such as `show()` or `count()` causes Spark to execute the required plan:

```scala
orderedReport.show(20, truncate = false)
```

## 4. Common DataFrame transformations

The classifications describe usual behavior. The physical plan can change because of the data source, statistics, partitioning, join strategy, and Adaptive Query Execution.

| Method | Purpose | Usual execution shape | Example |
| --- | --- | --- | --- |
| `select` | Choose or calculate columns | Narrow when expressions are row-local | `df.select(col("quantity"), col("sales_amount"))` |
| `selectExpr` | Select using SQL expressions | Narrow when expressions are row-local | `df.selectExpr("quantity * unit_price AS amount")` |
| `filter` / `where` | Keep matching rows | Narrow | `df.filter(col("quantity") >= 4)` |
| `withColumn` | Add or replace one column | Narrow when the expression is row-local | `df.withColumn("amount", col("quantity") * col("unit_price"))` |
| `withColumnRenamed` | Rename a column | Narrow | `df.withColumnRenamed("quantity", "units")` |
| `drop` | Remove columns | Narrow | `df.drop("shipping_days")` |
| `distinct` | Remove duplicate complete rows | Usually wide | `df.distinct()` |
| `dropDuplicates` | Remove duplicates using selected keys | Usually wide | `df.dropDuplicates("order_number", "order_line_number")` |
| `join` | Combine matching rows | Plan-dependent | `facts.join(products, Seq("product_key"), "left")` |
| `groupBy` | Define aggregation groups | Returns a grouped-data builder | `df.groupBy(col("category_key"))` |
| `agg` | Calculate grouped or whole-DataFrame aggregates | Usually wide after `groupBy` | `.agg(sum(col("sales_amount")))` |
| `orderBy` / `sort` | Create a global ordering | Wide | `df.orderBy(col("sales_amount").desc)` |
| `sortWithinPartitions` | Sort inside each current partition | Narrow | `df.sortWithinPartitions(col("order_number"))` |
| `unionByName` | Append rows by matching column names | Usually narrow | `current.unionByName(previous)` |
| `limit` | Keep at most a specified number of rows | Lazy transformation | `df.limit(10)` |
| `repartition` | Redistribute rows into new partitions | Wide | `df.repartition(8, col("customer_key"))` |
| `coalesce` | Reduce the partition count | Usually narrow | `df.coalesce(2)` |
| `sample` | Select a sample | Usually narrow | `df.sample(0.1, seed = 42L)` |

### Filtering

Use a `Column` expression for type-aware, composable conditions:

```scala
val filteredSales = factSalesDf.filter(
  (col("quantity") >= 4) &&
    (col("sales_amount") > 100)
)
```

Spark also accepts a SQL expression string:

```scala
val filteredSales = factSalesDf.filter(
  "quantity >= 4 AND sales_amount > 100"
)
```

The Column form is generally easier for IntelliJ to autocomplete and for application code to compose.

### Selecting and deriving columns

```scala
val salesReport = factSalesDf.select(
  col("order_number"),
  col("customer_key"),
  col("product_key"),
  col("quantity"),
  col("unit_price"),
  (col("quantity") * col("unit_price")).alias("calculated_sales_amount")
)
```

### Renaming and casting

```scala
val typedSales = rawSales
  .withColumnRenamed("qty", "quantity")
  .withColumn("quantity", col("quantity").cast("int"))
  .withColumn("unit_price", col("unit_price").cast("decimal(12,2)"))
```

## 5. Common actions and terminal operations

| Operation | Purpose | Important caution |
| --- | --- | --- |
| `show(n, truncate)` | Display rows in the console | Runs the required plan even though output is bounded |
| `count()` | Return the row count as a local `Long` | Usually processes the full required input |
| `first()` / `head()` | Return one row to the driver | Fails or needs careful handling when no row exists, depending on the method used |
| `head(n)` / `take(n)` | Return several rows to the driver | Safe only when `n` is deliberately bounded |
| `collect()` | Return every result row to the driver | Can exhaust driver memory; do not use for an unbounded or unproven result |
| `foreach` / `foreachPartition` | Run code against result rows | Task retries can repeat external side effects |
| `write...save()` | Write files or another data source | Executes the plan and creates external state |
| `write...saveAsTable()` | Publish a table through a catalog | Catalog, storage, and write-mode behavior must be understood |

Inspection helpers are also important:

```scala
factSalesDf.printSchema()
factSalesDf.explain("formatted")
```

`printSchema()` displays the resolved schema. `explain()` displays the query plan and is where you look for scans, filters, exchanges, sorts, and join strategies.

## 6. Common Spark SQL functions

### Columns and literals

| Function | Purpose | Example |
| --- | --- | --- |
| `col` | Refer to a named column | `col("quantity")` |
| `lit` | Create a literal value | `lit("training")` |
| `expr` | Parse a SQL expression into a Column | `expr("quantity * unit_price")` |

### Conditions and missing values

| Function or Column method | Purpose | Example |
| --- | --- | --- |
| `when(...).otherwise(...)` | Conditional result | `when(col("quantity") >= 4, "large").otherwise("small")` |
| `coalesce` | Return the first non-null value | `coalesce(col("phone"), lit("Unknown"))` |
| `isNull` / `isNotNull` | Test SQL null | `col("shipping_date").isNull` |
| `isnan` | Test floating-point NaN | `isnan(col("measurement"))` |

`functions.coalesce` chooses the first non-null column value. `df.coalesce(2)` reduces DataFrame partitions. The identical name hides two unrelated operations.

### Strings

| Function | Purpose |
| --- | --- |
| `trim`, `ltrim`, `rtrim` | Remove surrounding whitespace |
| `lower`, `upper`, `initcap` | Normalize letter case |
| `length` | Calculate string length |
| `concat`, `concat_ws` | Combine values |
| `split` | Split text into an array |
| `substring` | Extract part of a string |
| `regexp_extract`, `regexp_replace` | Extract or replace using a regular expression |

```scala
val cleanedProducts = productDf
  .withColumn("product_name", trim(col("product_name")))
  .withColumn("normalized_name", upper(col("product_name")))
```

### Dates and timestamps

| Function | Purpose |
| --- | --- |
| `to_date`, `to_timestamp` | Parse a date or timestamp |
| `current_date`, `current_timestamp` | Add the current processing date or time |
| `year`, `quarter`, `month`, `dayofmonth` | Extract a calendar component |
| `date_add`, `date_sub`, `add_months` | Shift a date |
| `datediff`, `months_between` | Compare dates |
| `date_format`, `date_trunc` | Format or bucket time values |

### Aggregates

| Function | Purpose |
| --- | --- |
| `count`, `countDistinct` | Count rows or distinct values |
| `sum`, `sum_distinct` | Calculate a total |
| `avg` / `mean` | Calculate an average |
| `median` | Calculate the middle value |
| `min`, `max` | Find an extreme value |
| `first`, `last` | Select a value from a group; ordering must be handled deliberately |
| `collect_list`, `collect_set` | Gather group values into an array |

### Numeric functions

| Function | Purpose |
| --- | --- |
| `abs` | Absolute value |
| `round`, `bround` | Round a numeric value |
| `ceil`, `floor` | Round toward positive or negative infinity |
| `pow`, `sqrt` | Power and square root |
| `greatest`, `least` | Select the greatest or least expression per row |

## 7. Joins

When both DataFrames use the same join-column name, pass that name separately from the join type:

```scala
val salesWithProducts = factSalesDf.join(
  productDf,
  Seq("product_key"),
  "left"
)
```

The arguments are:

```text
DataFrame being joined | shared key columns | join type
productDf              | Seq("product_key") | "left"
```

Use aliases when the key names differ or when selected columns would otherwise be ambiguous:

```scala
val joined = factSalesDf.alias("sales")
  .join(
    productDf.alias("product"),
    col("sales.product_key") === col("product.product_key"),
    "left"
  )
  .select(
    col("sales.order_number"),
    col("product.product_name"),
    col("sales.sales_amount")
  )
```

| Join type | Rows retained |
| --- | --- |
| `inner` | Rows with matches on both sides |
| `left` / `left_outer` | Every left row; unmatched right values become null |
| `right` / `right_outer` | Every right row; unmatched left values become null |
| `full` / `full_outer` | Every row from both sides |
| `left_semi` | Left rows that have at least one match |
| `left_anti` | Left rows that have no match |

A dimension key should be unique before it is joined to a fact table. Duplicate dimension keys multiply fact rows and change totals.

```scala
val duplicateProductKeys = productDf
  .groupBy(col("product_key"))
  .count()
  .filter(col("count") > 1)

duplicateProductKeys.show(truncate = false)
```

Use a left-anti join to find fact rows with no matching dimension record:

```scala
val unmatchedProducts = factSalesDf.join(
  productDf,
  Seq("product_key"),
  "left_anti"
)
```

## 8. Grouping and aggregation

`groupBy` changes the output grain. This example starts with one row per sale line and produces one row per product category:

```scala
val categorySales = joined
  .groupBy(col("category_key"))
  .agg(
    sum(col("sales_amount")).alias("total_category_sales")
  )
  .orderBy(col("total_category_sales").desc)
```

`groupBy` returns a `RelationalGroupedDataset`, not a normal DataFrame. `agg` specifies the calculations and returns the aggregated DataFrame.

Several aggregates can be calculated together:

```scala
val categorySummary = joined
  .groupBy(col("category_key"))
  .agg(
    sum(col("sales_amount")).alias("total_category_sales"),
    avg(col("sales_amount")).alias("average_line_sales"),
    count(lit(1)).alias("sales_line_count")
  )
```

## 9. Filtering grouped results against their overall average

This expression is not valid:

```scala
optionC.filter(
  col("total_category_sales") < avg(col("total_category_sales"))
)
```

`filter` evaluates a condition for each row, while `avg` must aggregate across multiple rows. Spark cannot place an aggregate directly inside the equivalent of a SQL `WHERE` clause. The returned DataFrame was also not assigned, so calling `optionC.show()` afterward would still display the original DataFrame.

For the current warehouse, `optionC` contains only a few product-category rows. Calculate the one-value average first, bring that bounded scalar to the driver, and then use it as a literal in the row filter:

```scala
val averageCategorySales = optionC
  .agg(
    avg(col("total_category_sales"))
      .cast("double")
      .alias("average_category_sales")
  )
  .first()
  .getAs[Double]("average_category_sales")

val belowAverageCategories = optionC.filter(
  col("total_category_sales") < lit(averageCategorySales)
)

belowAverageCategories.show(truncate = false)
```

The execution boundary is important:

```text
optionC.agg(avg(...)) -> one-row distributed DataFrame
first()               -> action returning one Row to the driver
getAs[Double](...)     -> local Double scalar
lit(...)              -> scalar placed back into a Spark Column expression
filter(...)           -> new lazy DataFrame
show()                 -> action executing the filtered plan
```

Do not generalize this into collecting large results. It is appropriate here because exactly one aggregate value crosses into the driver.

Aggregate functions do not all return the same JVM type. For example, the current `median` expression returns a `Double`, so reading it with `getDecimal` causes a `ClassCastException`. Give the result a name and use the getter that matches its schema:

```scala
val medianResult = optionC.agg(
  median(col("total_category_sales")).alias("median_category_sales")
)

medianResult.printSchema()

val medianCategorySales = medianResult
  .first()
  .getAs[Double]("median_category_sales")

val belowMedianCategories = optionC.filter(
  col("total_category_sales") < lit(medianCategorySales)
)
```

Use `printSchema()` when an aggregate's output type is uncertain. `getDouble` or `getAs[Double]` reads a Spark `DoubleType`; `getDecimal` reads a Spark `DecimalType` backed by `java.math.BigDecimal`.

An alternative that keeps the comparison in the DataFrame API is to calculate the one-row aggregate and cross join it to every category row:

```scala
import org.apache.spark.sql.functions.broadcast

val categoryAverage = optionC.agg(
  avg(col("total_category_sales")).alias("average_category_sales")
)

val belowAverageCategories = optionC
  .crossJoin(broadcast(categoryAverage))
  .filter(col("total_category_sales") < col("average_category_sales"))
  .drop("average_category_sales")
```

The cross join is safe only because the right side is guaranteed to contain one row. A cross join between two ordinary multi-row datasets can cause a large Cartesian-product explosion.

## 10. Ordering and top-N results

`orderBy` creates a global ordering for the returned DataFrame:

```scala
val highestCategorySales = categorySales
  .orderBy(
    col("total_category_sales").desc,
    col("category_key").asc
  )
  .limit(5)
```

The second ordering expression is a deterministic tie-breaker. Without it, tied categories can appear in either order.

`sortWithinPartitions` is less expensive but does not create a global order:

```scala
val locallySorted = factSalesDf.sortWithinPartitions(
  col("order_number").asc,
  col("order_line_number").asc
)
```

## 11. Null handling

SQL null is not equal to any value, including another null. Use the Column null methods:

```scala
val shippedSales = factSalesDf.filter(
  col("shipping_days").isNotNull
)

val pendingSales = factSalesDf.filter(
  col("shipping_days").isNull
)
```

Fill a known default only when that default is semantically correct:

```scala
val filled = factSalesDf.na.fill(
  Map("shipping_days" -> 0)
)
```

Do not treat zero, an empty string, `NaN`, and null as interchangeable. Each represents a different data condition.

## 12. Reading and writing

### JDBC read

```scala
val factSalesDf = spark.read.jdbc(
  jdbcUrl,
  "gold.fact_sales",
  jdbcProperties
)
```

This creates a source plan. Calling `show`, `count`, or another action makes Spark query PostgreSQL. A large JDBC source needs deliberate parallel-read bounds and must respect the database's connection capacity.

### File write

```scala
categorySales.write
  .mode("overwrite")
  .parquet("output/category-sales")
```

The `write` property creates a writer. The terminal `parquet(...)` call performs the write and therefore executes the plan.

## 13. Persistence and partitions

Cache a DataFrame only when its computed result will be reused enough to justify storage and recomputation costs:

```scala
val reusableJoined = joined.persist(StorageLevel.MEMORY_AND_DISK)

reusableJoined.count() // Materializes the persisted result.
reusableJoined.groupBy("category_key").count().show()
reusableJoined.groupBy("customer_key").count().show()

reusableJoined.unpersist()
```

Partition methods solve different problems:

```scala
val redistributed = df.repartition(8, col("customer_key")) // Full redistribution.
val fewerPartitions = df.coalesce(2)                        // Usually avoids a full shuffle.
```

Do not choose a partition count only because it produces a preferred number of output files. Consider input size, skew, executor parallelism, shuffle size, and downstream file-size requirements.

## 14. Common mistakes

### Ignoring a returned DataFrame

```scala
// Avoid: filter returns a new DataFrame, but the result is discarded.
optionC.filter(col("total_category_sales") < 1000)
optionC.show()

// Prefer: capture and use the result.
val smallCategories = optionC.filter(col("total_category_sales") < 1000)
smallCategories.show()
```

### Using `var` for an immutable pipeline

```scala
// Harder to inspect because one name changes meaning.
var result = factSalesDf
result = result.filter(col("quantity") >= 4)
result = result.select("customer_key", "sales_amount")

// Clear stage ownership and lineage.
val filtered = factSalesDf.filter(col("quantity") >= 4)
val projected = filtered.select("customer_key", "sales_amount")
```

### Putting the join type inside the key list

```scala
// Avoid: Spark treats both strings as column names.
facts.join(products, Seq("product_key", "left"))

// Prefer: the key list and join type are separate arguments.
facts.join(products, Seq("product_key"), "left")
```

### Collecting unbounded data

```scala
// Avoid unless the result is already proven small.
val everyRow = factSalesDf.collect()

// Prefer bounded inspection.
factSalesDf.show(20, truncate = false)
```

### Assuming a join preserves row count

Check key uniqueness and unmatched rows before assuming a fact-to-dimension join is one-to-one or many-to-one. Duplicate dimension keys can multiply facts, and an inner join can silently remove unmatched facts.

## 15. Compact end-to-end example

```scala
import org.apache.spark.sql.functions.{col, sum}

val report = factSalesDf
  .filter(col("quantity") >= 4)
  .join(productDf, Seq("product_key"), "left")
  .join(customerDf, Seq("customer_key"), "left")
  .groupBy(
    col("product_category"),
    col("country")
  )
  .agg(
    sum(col("sales_amount")).alias("total_sales")
  )
  .orderBy(
    col("total_sales").desc,
    col("product_category").asc,
    col("country").asc
  )

report.show(20, truncate = false)
```

The output grain is one row per product-category and customer-country combination. Filtering is normally narrow, the joins are plan-dependent, grouping normally shuffles, global ordering normally shuffles and sorts, and `show()` triggers execution.

## 16. Debugging checklist

1. Run `printSchema()` and verify exact column names and types.
2. Confirm whether the failing name belongs to a DataFrame, `functions`, `Column`, or grouped dataset.
3. Capture every transformation's returned DataFrame.
4. Use aliases when a join creates duplicate column names.
5. Check join-key uniqueness and unmatched keys.
6. Use `explain("formatted")` to inspect scans, exchanges, sorts, and join strategies.
7. Reduce the problem to `select`, `filter`, and `show(5)` before rebuilding a longer chain.
8. Read the first meaningful exception rather than treating Spark startup logs as the error.
