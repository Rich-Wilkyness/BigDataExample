## Part 10 — Short Answer Questions

Answer each question in **1–3 sentences**.

1. What is a case class, and why is it useful for representing data?
    - A case class is a concise way to represent immutable data. Scala automatically provides useful features such as copy, readable toString, equality comparison, and pattern matching.
2. What is a trait?
   - part of inheritance, a class can inherit multiple traits. It's important to keep traits small
   - A trait defines a shared contract or reusable behavior.
3. What is the difference between a trait and a regular class?
   - A regular class can be instantiated and usually represents a concrete object. 
   - A trait cannot be instantiated directly and is primarily inherited by classes or objects. 
   - Both may contain abstract and implemented members.
4. Why can both `PostgresSource` and `CSVSource` be stored in a `List[DataSource]`?
    - Both classes can be stored in List[DataSource] because they extend DataSource. Therefore, each instance is also considered a DataSource.
5. What is the difference between `Some` and `None`?
    - Some and None are the two forms of Option. 
    - Some(value) contains a value,
    - None represents an absent value.
6. What is the difference between `map` and `flatMap`?
    - map transforms every element while preserving the collection structure. 
    - flatMap transforms every element and then removes one level of nesting.
7. What is a companion object?
    - A companion object has the same name as a class and is defined in the same scope. 
    - It can provide factory methods and access the class’s private members.
8. What is the purpose of a sealed trait/class?
    - it creates exhaustive match/cases, allowing for a more declarative approach
    - A sealed trait or class restricts where its direct subtypes can be defined. 
    - This lets the compiler determine whether a pattern match handles every possible case.
9. What is the difference between method **overloading** and method **overriding**?
    - overloading is creating multiple functions with the same name, but can differ in args, return types, and body. 
      - A different return type alone cannot overload a method.
    - Overriding replaces an inherited method with a new implementation using the same signature. 
10. What is a closure?
    - A closure is a function that remembers variables from the surrounding scope (must be in accessible scope -> more than what is trying to access it)
11. What does it mean to say that a function is **curried**?
    - like hot potatoe for args in a function. A single function can be broken up into two or more (depending on the number of args), then you can supply the fields that apply and create unique functions like texasTaxes vs floridaTaxes.
    - A curried function divides its arguments into multiple parameter lists. This allows some arguments to be supplied now and the remaining arguments later
12. What does `import spark.implicits._` provide when working with Spark?
    - provides common implicit conversions and encoders. It enables features such as .toDS(), .toDF(), and $"columnName".
13. Why does Spark need an `Encoder` when creating a typed `Dataset`?
    - An Encoder tells Spark how to convert typed JVM objects into Spark’s internal row format and back again. 
    - It also gives Spark schema information for a typed Dataset.
14. Explain one way a case class could be used in a real Spark data pipeline.
    - define incoming data types (at the border of your app) to ensure data consistency moving forward by row
