## Part 1 — Core AWS Concepts

Answer each question in **2–4 sentences**.

1. What is an **AWS Region**? Why might a company choose one region instead of another?
    - region is where the server is located, a company wants their servers as close to where most of their users are. 

> **corrections**: Proximity is a valid reason. A Region is a geographic area containing multiple Availability Zones, rather than the location of one server. Also consider data-residency requirements, service availability, and regional pricing.

2. What is **IAM (Identity and Access Management)**?
    - a way to set a users identity with either user and/or roles.
    - then access is controlled via the policies assigned

> **correct**: You identified both identity and policy-based access. IAM manages identities and authorization; policies describe allowed or denied actions on resources.

3. Explain the difference between:
   - IAM user - individual user
   - IAM role - group of users (Data_Engineer, Data_Analyst, etc.)
   - IAM policy - what a user or role can do (Can read/write to this S3 bucket)

> **corrections**: Your policy example is correct. A role is an identity that trusted people or services assume, normally using temporary credentials; it is not a group of users. An IAM group collects IAM users, while a role such as Data_Engineer can be assumed by different authorized principals.

4. What is a **VPC (Virtual Private Cloud)**? Why would an organization place resources such as EC2 instances inside a VPC?
    - Like a secure kube pod on the cloud, can run multiple related resources like many EC2 instances that are interrelated and benifit from closeness

> **corrections**: A VPC is a logically isolated virtual network, not a Kubernetes pod. It provides network organization through subnets, routes, and traffic controls; placing resources there helps control connectivity and exposure. Resources in one VPC can span multiple Availability Zones, so physical closeness is not its defining feature.

5. What does **serverless** mean? What is the major advantage of serverless services compared with infrastructure that must remain running continuously?
    - it means you as the user do not need to manage on prem hardware. Whatever software you want to run you can, and are able to scale up or down on need basis. 
    - Depending on your needs this can reduce upfront costs, fast scaling, and reduce cost if you don't need continuous use of the hardware.

> **corrections**: Your potential cost and scaling benefits are reasonable. The defining feature is that AWS manages server provisioning and operation for the service. EC2 also avoids owning on-premises hardware, but still exposes VMs to manage; serverless services also restrict supported runtimes, execution limits, and configuration rather than allowing arbitrary software.

EMR also offers Serverless and EKS deployment models. See [EMR overview](https://docs.aws.amazon.com/emr/latest/ManagementGuide/emr-what-is-emr.html).

### AWS Glue

4. What is AWS Glue?
    - AWS way of using Spark

> **additions**: That describes its Spark-job capability, but Glue is broader: a managed data-integration service with ETL jobs, crawlers, and the Data Catalog. Its Spark jobs use Apache Spark with AWS integrations.

5. What is a **DPU (Data Processing Unit)**?
    - amount of data that can be processed by 4 vCPUs and 16 GB of memory per hour?

> **corrections**: A standard DPU is a capacity unit corresponding to 4 vCPUs and 16 GB of memory, not an amount of data processed per hour. DPU-hours combine allocated capacity with billed duration; throughput depends on the workload. See [Glue worker properties](https://docs.aws.amazon.com/glue/latest/dg/add-job.html).

6. Why does Glue allow developers to think less about individual servers or cluster nodes?
    - Glue auto allocates partitioning for you, where in Spark you are required for defining the partitions, number of executors, RAM, and more

> **corrections**: Glue manages the underlying infrastructure and supplies workers for the job. You still choose relevant worker/capacity settings and may need to tune Spark partitions, shuffles, and memory behavior. Ordinary Spark also has defaults and automatic behavior; manually defining every partition is not required.

7. Consider these two workloads:

Which workload is a more natural candidate for EMR, and which is a more natural candidate for Glue? Explain why.
- A = EMR (typically better for continuous work)
- B = Glue

> **additions**: Your A/B choices match the classroom starting rule. Explain that continuous work may benefit from sustained cluster capacity, while a short nightly Glue job can release managed compute afterward. The rule is not absolute: Glue supports streaming, and EMR supports transient clusters and Serverless jobs.

# Part 4 — Data Warehousing and Databases

### Redshift

1. What is Amazon Redshift?
    - an analytical SQL warehouse that uses massively parallel processing. can be used as a general substitute for snowflake

> **correct**: The analytical SQL/MPP description is right. Redshift and Snowflake overlap as warehouse choices, but they are not drop-in replacements; SQL behavior, integrations, administration, and pricing differ.

2. What does **MPP (Massively Parallel Processing)** mean?
    - it is able to spread work across a cluster (several different computers) to complete a single job in a massive way

> **correct**: Yes: multiple compute resources execute portions of a query or workload in parallel and combine results. Data distribution and skew determine how effectively that parallelism is used.

3. What is the purpose of the Redshift `COPY` command?
    - to copy data from S3 and other sources into redshift tables that then can be processed

> **correct**: Yes—COPY bulk-loads supported source data into Redshift tables. The destination table must already exist, and the load needs compatible data and permissions.

4. Explain one advantage of **Redshift Serverless** compared with maintaining a continuously running provisioned Redshift cluster.
    - same addvantages as most serverless, less headcount to manage your hardware, can scale up and down based on need, etc.

> **additions**: Managed capacity and scaling are valid benefits. For on-demand Redshift Serverless, compute is charged by capacity used over time rather than continuously maintaining provisioned cluster compute; storage is billed separately. Both provisioned and serverless services already reduce physical-hardware maintenance. See [on-demand billing](https://docs.aws.amazon.com/redshift/latest/mgmt/serverless-billing-on-demand.html).

5. Research question: What similarities exist between **Amazon Redshift Serverless** and **Google BigQuery**?
    - not sure, both use SQL and massively parallel processing

> **additions**: Those similarities are valid. Add that both provide managed/serverless analytical capabilities, distributed execution, and separate storage/compute responsibilities, reducing the need to administer servers. Their pricing units and configuration differ. Compare [BigQuery overview](https://docs.cloud.google.com/bigquery/docs/introduction) with [Redshift Serverless billing](https://docs.aws.amazon.com/redshift/latest/mgmt/serverless-billing-on-demand.html).

### RDS

6. What is Amazon RDS?
    - relational database system. essentially an EC2 with a SQL database engine/image running on it

> **corrections**: RDS stands for Relational Database Service. It is a managed service for supported relational engines, not an EC2 VM you administer directly. AWS handles infrastructure and supported maintenance tasks; you manage database schemas, access, and workload choices. See [RDS overview](https://docs.aws.amazon.com/AmazonRDS/latest/UserGuide/Welcome.html).

7. Why might an application running on EC2 use RDS instead of storing its application data directly on the EC2 instance?
    - RDS is more persistent than a EC2, the main question should be, why RDS vs EBS.

> **corrections**: EC2 with retained EBS can also store persistent database data. RDS versus EBS compares different layers: RDS is a managed database service; EBS is block storage. The useful comparison is RDS versus operating your own database on EC2/EBS, where your team owns installation, patching, backups, and availability configuration.

8. Name at least three relational database engines available through Amazon RDS.
    - MySQL, Postgres, Oracle

> **correct**: All three are supported RDS engine choices. PostgreSQL is the formal engine name commonly shortened to Postgres.

# Part 5 — Athena, Glue and Schema-on-Read

This section is particularly important because these services are commonly used together.

Answer the following:

1. What is Amazon Athena?
    - used to query S3 or another source, not meant to process large amounts of data

> **corrections**: Your query-service idea is right, but Athena can query large datasets using distributed execution. It is commonly used for SQL over S3 and can query other sources through supported federated connectors. It is not limited to small data; layout, scan cost, and performance determine suitability.

2. Does Athena store the actual data that it queries?
    - no, typically on S3

> **correct**: Correct for the usual S3 external-table pattern: source data remains in S3, and the catalog holds its definition. Query results or CTAS output may also be persisted, so distinguish source storage from results.

3. Explain **schema-on-read** in your own words.
    - it uses the schema from a downstream to help interpret upstream data. so using silver schema to interpret a raw-bronze table of data

> **corrections**: Schema-on-read means applying a schema when reading stored data rather than enforcing all of that structure at initial storage. The schema must describe the data being read; it does not automatically come from Silver. Bronze and Silver can have different formats, columns, and types.

4. What does a **Glue Crawler** do?
    - helps read schemas when you have not defined them?

> **additions**: You are on the right track. A crawler inspects configured sources, infers schemas and partition information where applicable, and creates or updates definitions in the Glue Data Catalog. Inference needs review, and a crawler is optional when you define metadata explicitly.

5. What information is stored in the **Glue Data Catalog**?
    - metadata about tables, schemas, etc.

> **correct**: Yes. Examples include columns/types, data locations, file-format information, and partitions. The catalog stores descriptions, not the actual CSV or Parquet contents.

6. How is the Glue Data Catalog conceptually related to the **Hive Metastore**?
    - both store metadata that allows for the schema to be separate from the data itself

> **correct**: Yes—both supply table metadata that query engines use to locate and interpret separately stored data.

7. Suppose the following file arrives:

`S3 → s3://company-bronze/orders/orders.csv`

Explain how the following components could work together to make this data queryable:

**S3 → Glue Crawler → Glue Data Catalog → Athena**

1. Lands in S3 bucket as shown
2. Athena attempts to query the raw data
3. Glue Crawler checks the Glue Data Catalog for the downstream schema to assist in parsing the raw data

> **corrections**: Reverse the discovery/query order: after the CSV lands, a configured crawler inspects that source and creates or updates its table definition in the Data Catalog. Athena then uses the catalog definition to read the CSV in S3. Athena does not automatically launch a crawler, and the crawler does not need a downstream Silver schema. See [Athena table creation](https://docs.aws.amazon.com/athena/latest/ug/creating-tables.html).

# Part 6 — Event-Driven Architecture

Amazon **EventBridge** allows actions to be triggered when events occur.

Consider this scenario:

> A company receives a new sales file in an S3 bucket every evening. When the file arrives, the company wants AWS to automatically begin processing it.

Answer:

1. What role could EventBridge play?
    - verify the S3 notification, verify the file exists, then connects it to the next step, Glue, Redshift, etc.

> **corrections**: EventBridge matches event fields against rules and routes matching events to configured targets. It does not automatically inspect file contents or verify that the file still exists; a handler or workflow performs such checks if needed. S3 event delivery to EventBridge must be enabled. See [S3 and EventBridge](https://docs.aws.amazon.com/AmazonS3/latest/userguide/EventBridge.html).

2. What AWS service could process the file without maintaining a continuously running cluster?
    - Glue

> **correct**: Yes. A Glue Spark job can process the file with managed compute rather than a continuously maintained cluster.

3. Where could the processed data be stored?
    - S3 bucket in a silver layer bucket or RDS

> **correct**: Both are possible destinations with the right configuration. Curated S3 data is the direct fit for the usual Athena lake-query pattern; writing to RDS requires database connectivity and credentials and serves a different storage/consumer design.

4. How could Athena later query that data?
    - target the location of the output with the correct schema

> **additions**: Correct core idea. For S3 output, register a table in the Glue Data Catalog with the output location, schema, format, and relevant partitions; Athena uses that definition to query the files. For RDS output, a supported federated connector and its access/network configuration are needed.
