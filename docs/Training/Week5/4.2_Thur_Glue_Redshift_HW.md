## The pipeline and the concepts

```text
Stored JSON snapshots in S3 Bronze
          │
          │ Glue Spark job: flatten station arrays, join metadata, derive flags
          ▼
Structured Parquet files in S3 Silver
          │
          │ Glue load job + JDBC connection
          │ stages files in S3, then Redshift COPY loads them
          ▼
Your table in a Redshift database/schema
          │
          └─ Optional analytical Gold model once the load works
```

| Term | Meaning for this homework |
| --- | --- |
| Bronze | Preserved API snapshots: one JSON document per feed per ingestion |
| Silver | One row per station per ingestion snapshot, with flattened fields and derived flags |
| Gold | Data prepared for consumption in Redshift; first prove the load, then describe any further business model |
| Workspace | Your named resources and local working files; this pipeline does not require a separate EMR notebook Workspace |
| Namespace | Redshift Serverless’s database/storage and associated identity settings |
| Workgroup | Redshift Serverless’s compute endpoint and networking configuration |
| Glue connection | Saved JDBC credentials/endpoint and subnet/security-group settings |
| IAM role | What an AWS service can do; distinct from your console identity and the database login |
| Subnet | An address range in a VPC, located in one Availability Zone |
| Route table | Determines where traffic from a subnet goes |
| Security group | Controls allowed traffic to/from network interfaces |
| S3 gateway endpoint | A route from a VPC to S3 without needing a NAT gateway |

The JDBC connection carries database access information. The connector also needs S3 access for staging. Saving the connection does not prove either route works. See [Glue’s Redshift integration](https://docs.aws.amazon.com/glue/latest/dg/aws-glue-programming-etl-connect-redshift-home.html) and [Redshift namespaces/workgroups](https://docs.aws.amazon.com/redshift/latest/mgmt/serverless-workgroup-namespace.html).
