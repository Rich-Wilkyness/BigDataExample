Our architecture was:

**AWS Lambda → Amazon Kinesis Data Streams → AWS Glue Streaming → Amazon Aurora PostgreSQL**

This homework focuses primarily on understanding the architectural decisions and engineering principles behind the pipeline.

What is a microbatch?

**10. Delivery guarantees (5 points)**

Research the concepts of:

- At-most-once processing = the data will be processed one time, if a failure occurs, data can be lost.
- At-least-once processing = ensures that data is processed, this comes at the expense that you might duplicate work.
- Exactly-once processing = this requires more setup, but ideally combines the upsides of both approaches without the bad.

Explain the differences.

Our Glue job inserted records into PostgreSQL using ordinary SQL `INSERT` statements. What could happen if a batch was successfully inserted but the streaming job failed before its checkpoint was committed?

**corrections:** At-most-once means zero or one processing attempt/effect within the stated boundary, so delivery can be lost. At-least-once allows retries and duplicates. Exactly-once means each logical event affects the result once within a defined boundary; it does not necessarily mean the code runs only once. Your duplicate-INSERT answer is right. A uniqueness constraint might instead reject the repeat.

**additions:** Explain why the database commit and checkpoint commit are separate here. Consider a stable event identity, a uniqueness constraint, and deliberate conflict handling so a retry has the same final effect. A checkpoint alone does not make arbitrary PostgreSQL writes exactly once. [AWS duplicate recovery](https://docs.aws.amazon.com/streams/latest/dev/kinesis-record-processor-duplicates.html), [Spark sink guarantees](https://spark.apache.org/docs/latest/streaming/apis-on-dataframes-and-datasets.html#using-foreach-and-foreachbatch).
