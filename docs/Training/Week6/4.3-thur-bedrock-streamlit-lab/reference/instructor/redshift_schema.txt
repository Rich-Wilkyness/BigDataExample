DATA DEFINITIONS:
- snapshot_timestamp is the timestamp of a station observation.
- bikes_available is the number of available bikes at that observation.
- ebikes_available is the number of available electric bikes.
- docks_available is the number of available docking spaces.
- utilization_pct is the recorded utilization percentage.
- Each fact_station_snapshot row represents a station observation at a timestamp.
- Use gold tables for dimensional analysis; public.citibike_station_snapshot_v2 is a denormalized alternative.
- Do not sum bikes_available across multiple timestamps and describe the result as a current bike count.


DATA GRAIN AND QUERY RULES:

gold.dim_station:
- One row per station_id is intended.
- station_id identifies a station.

gold.fact_station_snapshot:
- Time-series fact table.
- Each row represents one observation of a station at a specific snapshot_timestamp.
- A station appears many times across different timestamps.
- Intended grain: (station_id, snapshot_timestamp).

QUERY RULES:
- When the user asks for "top stations", "bottom stations",
  or a ranking of stations, return one row per station
  unless the question explicitly requests individual observations.
- For current/latest availability, use ROW_NUMBER()
  partitioned by station_id and ordered by
  snapshot_timestamp DESC, then filter to rn = 1.
- For historical averages, use AVG() and GROUP BY station_id.
- Never rank raw snapshot rows when the user asks
  for a ranking of stations.
- Do not use DISTINCT to conceal duplicates caused
  by incorrect joins or incorrect query grain.
- For time-series questions, include the relevant
  timestamp or time grouping.
- Join fact_station_snapshot to dim_station on station_id.
- Join fact_station_snapshot to dim_date on date_key.
