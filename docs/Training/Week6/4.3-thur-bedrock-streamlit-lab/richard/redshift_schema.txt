DATA GRAIN AND DEFINITIONS:
- incremental_dim_station has one row per station_id, with latest accepted station_name and capacity (Type 1 attributes).
- incremental_dim_date has one row per snapshot_date, a UTC capture date; there is no date_key column.
- incremental_fact_station_snapshot has one observation per (station_id, snapshot_timestamp).
- snapshot_timestamp is the UTC capture timestamp from the source filename, not the station's last_reported time.
- bikes_available, ebikes_available and docks_available are counts at that capture.
- capacity_at_capture is historical capacity on the fact; capacity on the station dimension is its latest accepted value.
- utilization_pct records bicycle availability as a percentage of capacity, not trip demand or rentals.
- is_empty, is_full and is_operational are recorded station indicators.
- batch_id records the accepted processing batch.

QUERY RULES:
- Use only the listed gold.incremental_* tables and their actual columns.
- Join station dimension on station_id and date dimension on snapshot_date.
- Station rankings should return one row per station unless observations are explicitly requested.
- For latest availability, select the latest observation per station using a timestamp ordering before ranking stations.
- Latest stored availability is not necessarily live availability; include the observation timestamp.
- For historical station averages, aggregate observations per station with AVG.
- Do not sum bikes_available across timestamps and describe that as a current bike count.
- Do not use DISTINCT to hide an incorrect join or query grain.
- Include the relevant time grouping for time-series questions.
- Do not invent a date_key, station_name on the fact, or instructor table names.
