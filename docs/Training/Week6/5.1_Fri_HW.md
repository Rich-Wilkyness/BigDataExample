    - terraform uses a provider to link to the cloud architecture. Then it uses names to link with existing resources or creates new resources and configurations

- Data ingestion: Why Lambda is appropriate for lightweight API ingestion.

    > **Addition:** Good fit for a short API fetch followed by an S3 write: Lambda runs in response to an invocation without you managing a persistent server. Be more precise about the trigger: a schedule can invoke it periodically, and an S3 object-created event can invoke it after an upload. A local directory change does not automatically trigger Lambda. Account for API timeouts and duplicate invocations.

- Orchestration versus transformation: Why Step Functions coordinates the workflow while Glue performs the data processing.
    - why is a hard question to answer, that is their purpose. Step functions were designed to orchestrate steps in a pipeline and Glue was designed to process data.

    > **Addition:** Your division of responsibilities is correct. Explain the practical reason with a failure: Step Functions decides whether to retry a failed job, run a later task, or report failure; Glue performs operations such as parsing, deduplication, and writing transformed records. Separating them lets you change workflow control without rewriting the transformation.

- Incremental processing: Why production pipelines should not reprocess all historical data every time.
    - because you would be duplicating work that has already been done. 

    > **Addition:** Correct: processing only new or changed input reduces repeated compute and makes frequent updates practical. Distinguish repeated work from duplicate output records: a complete overwrite might repeat work without duplicating rows. An incremental pipeline still needs a checkpoint or processed-input record, safe replay, and a policy for late data or backfills.

- Medallion architecture: The purpose of Bronze, Silver, and Gold data layers.
    - separation of concerns and amount that data processing has occured; how refined the data is, which allows you to go upstream or downstream based on what you are looking for.

    > **Addition:** Good explanation. Make the responsibilities concrete: Bronze preserves source payloads for investigation/replay, Silver standardizes and validates records, and Gold presents business-ready models and measures. Moving to Gold should give data a clearer business meaning, not merely place the same data in another folder.

- Dimensional modeling: Why analytical systems use fact and dimension tables.
    - the grain allows for easier queries as well as grouping related data in readable ways.

    > **Addition:** Grain is an important starting point. Fact tables hold measurements at a defined grain; dimensions supply descriptive attributes used to filter and group those measurements. In your saved Gold schema, one fact row is one station at one capture timestamp, while the station dimension supplies the station name. Correct joins preserve that grain and prevent accidental double counting.

- Analytics presentation: How Streamlit connects the underlying data platform to its users.
    - how? through using code to query the data and then generate tables

    > **Addition:** Yes. The application turns user selections into queries and presents tables, charts, and explanations with domain labels. Add that the interface can offer a controlled set of actions, so users do not need to know the warehouse schema or write SQL themselves.

### 2. Embeddings

An embedding is a numerical representation of text or other content.

Embeddings allow applications to compare the semantic similarity of questions and documents. For example, a question about station utilization may be semantically similar to documentation describing how utilization is calculated.
- TODO: can you describe this better? I'm not following.

> **Addition — embeddings step by step:** Start with a documentation sentence such as “bikes_available records bicycles ready to rent at capture time.” An embedding model converts that text into a list of numbers, called a vector. It also converts a question such as “Where can I pick up a bicycle?” into a vector. A similarity search compares the vectors mathematically to find potentially useful documentation even when the wording differs. The application then supplies the retrieved text to the generation model. Individual numbers are learned features, not named business columns, and similarity is not proof that a passage answers the question. See [Titan text embeddings](https://docs.aws.amazon.com/bedrock/latest/userguide/titan-embedding-models.html).

> **Addition — keep the objects separate:** Document text is the readable source; an embedding is its numerical search representation; retrieved context is the selected text sent to the LLM. Embedding documentation about bike counts does not calculate the station with the most bikes. That answer still requires an appropriately timed query over actual station observations.

### 3. Vector databases

A vector database stores embeddings and supports similarity searches.

Instead of looking only for exact keyword matches, a vector search can retrieve documents that are conceptually related to a user's question.

In our AWS architecture, we explored Amazon S3 Vectors as a way to store and retrieve embeddings.

### 4. Retrieval-Augmented Generation (RAG)

RAG combines information retrieval with an LLM.

A typical RAG workflow is:

**Plain Text**

```text
User Question
      |
      v
Create Question Embedding
      |
      v
Search Vector Database
      |
      v
Retrieve Relevant Documentation
      |
      v
Add Documentation to LLM Prompt
      |
      v
Generate Context-Aware Answer
```

RAG helps the model work with information that was not necessarily included in its original training data.

Our classroom application also explored local document retrieval as an alternative to embedding-based retrieval.

See [Bedrock's explanation of retrieval and generation](https://docs.aws.amazon.com/bedrock/latest/userguide/knowledge-base.html).

### 5. Amazon Bedrock

Amazon Bedrock provides managed access to foundation models through AWS APIs.

Our application uses Amazon Nova to generate Redshift SQL and explain query results. We also experimented with Amazon Titan embeddings for document retrieval.

Bedrock provides model inference; it does not replace Redshift, Glue, or Step Functions.
