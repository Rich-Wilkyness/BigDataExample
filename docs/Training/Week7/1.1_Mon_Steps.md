## 1. Confirm the training environment

**Azure portal:** Sign in to the instructor's directory. Open **Directories + subscriptions** and select the assigned training subscription. Check **Resource groups** for your existing group before creating anything.

The subsequent Tuesday lab recorded subscription `AzureTraining`, group `rg-adls-richard`, account `adlsricharda35b84`, and region East US 2 for storage. Treat these as captured values, not newly verified state. Use your assigned resources if they differ.

**Captured macOS CLI route:** Use an existing installation where available. The lecture's Debian `apt-get` installer is for Linux, not macOS.

```bash

```

**Checkpoint:** Your selected tenant/subscription is the intended training environment. If resource creation is denied, record the exact permission error and contact the instructor; installing the CLI again will not fix RBAC.

## 3. Create the resource group if missing

**Portal:** **Resource groups → Create**, select the training subscription, enter your group name and approved region, then **Review + create → Create**.

**Captured CLI equivalent:**

```bash
az group create --name "$RG" --location "$LOCATION"
```

Skip creation when the intended group already exists. Resource-group creation needs management-plane permission.

## 4. Create an HNS-enabled storage account if missing

**Portal:** **Storage accounts → Create**. Select the group, globally unique account name, approved region, Standard performance, and LRS redundancy for the captured lab. In the relevant advanced settings, enable **Hierarchical namespace**, require HTTPS, disable anonymous blob access, and disable storage account key access. Review and create. Field grouping varies by portal version.

**Captured CLI equivalent:**

```bash
az storage account create \
  --name "$STORAGE" \
  --resource-group "$RG" \
  --location "$LOCATION" \
  --sku Standard_LRS \
  --kind StorageV2 \
  --hns true \
  --https-only true \
  --allow-blob-public-access false \
  --allow-shared-key-access false

az storage account show \
  --name "$STORAGE" \
  --resource-group "$RG" \
  --query "{Name:name,HierarchicalNamespace:isHnsEnabled}" \
  --output table
```

**Checkpoint:** HNS is enabled on the intended account. Do not change shared account settings to reproduce an individual lab.

## 5. Confirm storage data access

**Portal:** Open the account's **Access control (IAM) → View my access**. The upload caller needs storage data permission, such as the instructor-approved Storage Blob Data Contributor role at an appropriate scope. A management role alone is insufficient for the Entra-based commands below.

If needed, ask the instructor to assign access. Role assignment requires privileges you may not have, and propagation can take time. ADF and Databricks will later need separate service-identity grants.

## 6. Create the container and directory

**Portal:** Open **Data storage → Containers**, create private container `bronze`, open it, and create `customers/raw`. If the browser creates one directory at a time, create `customers`, open it, then create `raw`. Use Entra user authentication when offered; account-key access is disabled in the captured configuration.

**Captured CLI equivalent:**

```bash
az storage fs create \
  --name "$CONTAINER" \
  --account-name "$STORAGE" \
  --auth-mode login

az storage fs directory create \
  --file-system "$CONTAINER" \
  --name "customers/raw" \
  --account-name "$STORAGE" \
  --auth-mode login
```

## 7. Upload the instructor CSV

**Portal:** Inside `bronze/customers/raw`, choose **Upload**, select the actual local customer CSV, and retain destination name `customers.csv`. Confirm the destination before overwriting any existing file.

**Captured CLI equivalent:** The downloaded file was named `customers (4).csv`; replace only the source with the actual local filename if it differs.

```bash
az storage fs file upload \
  --file-system "$CONTAINER" \
  --path "customers/raw/customers.csv" \
  --source "$HOME/Downloads/customers (4).csv" \
  --account-name "$STORAGE" \
  --auth-mode login

az storage fs file list \
  --file-system "$CONTAINER" \
  --path "customers/raw" \
  --account-name "$STORAGE" \
  --auth-mode login \
  --query "[].{Path:name,Bytes:contentLength}" \
  --output table
```

**Expected result:** `customers/raw/customers.csv` exists with a positive byte count. This verifies upload/storage access, not the customer's data quality. Your Mac's Downloads path is not a Databricks path.
