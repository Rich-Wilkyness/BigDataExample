# Azure Data Engineering — Homework and Final Pipeline Presentation

**Due:** Pipeline proposal before the next Azure class; completed project and presentation at the end of this week's Azure training.

## Part 1 — Review Today's Azure Lab

Today we covered Azure fundamentals, Azure CLI, Azure Data Lake Storage Gen2 (ADLS Gen2), and an introduction to Azure Databricks and Apache Spark.

Before the next class, make sure you can explain the following concepts:

1. **Azure architecture:** The differences between an Entra tenant, subscription, resource group, and individual Azure resources.
2. **Azure RBAC:** The differences between Contributor and Storage Blob Data Contributor, and why storage data access requires separate permissions.
3. **ADLS Gen2:** Storage accounts, containers, hierarchical namespaces, directories, and the `abfss://` URI format.
4. **Medallion architecture:** The purposes of Bronze, Silver, and Gold layers.
5. **Databricks and Spark:** Spark DataFrames, transformations, actions, Spark SQL, and the difference between local Pandas processing and distributed Spark processing.

### Practical verification

Make sure your Azure environment contains:

- An Azure resource group created using Azure CLI.
- An ADLS Gen2 storage account with hierarchical namespace enabled.
- A `bronze` container.
- A `customers/raw/` directory.
- A successfully uploaded `customers.csv` file.

Be prepared to demonstrate how to list the contents of your ADLS container and explain how Databricks could read the file.

**Optional practice:** Reproduce today's Databricks notebook demonstration, including creating a DataFrame, filtering records, adding a calculated column, aggregating results, and querying a temporary view with Spark SQL.

Do not delete or terminate shared Databricks resources.

## Part 2 — Propose Your Own Azure Data Pipeline

**Each student must submit an original idea for a data engineering pipeline that they will design, build, and present at the end of this week's Azure classes.**

The pipeline should address a realistic business or analytical problem. You may use publicly available datasets, synthetic data, APIs, or other accessible data sources.

Your proposal should include:

1. **Project title:** Give your pipeline a descriptive name.
2. **Business problem:** What problem does the pipeline solve, and who would use its output?
3. **Data source:** Where will the data originate? What format will it use (CSV, JSON, API, etc.)?
4. **Architecture:** Which Azure services will you use, and how will data move between them?
5. **Transformations:** What cleaning, validation, enrichment, or aggregation will your pipeline perform?
6. **Final output:** What useful dataset, report, dashboard, or analytical result will the pipeline produce?

Keep the initial proposal brief: approximately half a page to one page.

### Example project ideas

These are suggestions only. Students are encouraged to develop their own ideas.

- **Retail Sales Analytics:** Ingest transaction data, clean it, and calculate sales by region, product, and month.
- **Weather Data Pipeline:** Collect weather observations from a public API and analyze temperature trends.
- **Transportation Analytics:** Process trip records to identify busy routes, peak travel hours, and usage patterns.
- **Financial Transactions:** Process synthetic financial transactions and identify unusual activity.
- **Movie or Entertainment Analytics:** Ingest ratings or box-office data and calculate trends by genre and year.
- **E-commerce Customer Analytics:** Transform customer and order records to calculate customer lifetime value and purchasing patterns.

Projects should be achievable within the remaining training period. A small, fully working pipeline is preferable to a large, incomplete one.

## Part 3 — Build the Pipeline During This Week's Classes

Your project should demonstrate an end-to-end data engineering workflow.

### Minimum expected architecture

**Source → Bronze → Silver → Gold → Analytical Output**

- **Source:** A CSV, JSON file, public dataset, or API.
- **Bronze:** Raw data stored in ADLS Gen2.
- **Silver:** Data cleaned and transformed using Azure Databricks and PySpark.
- **Gold:** Aggregated or business-ready data suitable for analysis.
- **Output:** A meaningful query, summary, visualization, or report demonstrating the value of the processed data.

Students should aim to use Delta Lake tables in Databricks as we cover them during the week.

You are not required to use every Azure service. Additional services such as Azure Data Factory may be incorporated if covered in class and if time and permissions permit.

### Technical expectations

Your pipeline should demonstrate:

- Data ingestion into Azure storage.
- At least two meaningful data transformations.
- Basic data quality validation.
- An organized Bronze/Silver/Gold architecture.
- A working PySpark or Spark SQL component.
- A final analytical result that answers a business question.

Document any limitations, incomplete components, or steps that still require manual execution.

## Part 4 — Final Presentation and Live Demonstration

At the end of this week's Azure classes, **every student will present their pipeline to the class**.

Presentations must use PowerPoint or a comparable slide-based presentation system, such as Google Slides, Canva, or another suitable platform.

### Required presentation content

1. **Introduction and business problem:** Explain the purpose of your pipeline and its expected value.
2. **Architecture diagram:** Show the Azure services involved and the flow of data through the pipeline.
3. **Data source:** Describe the source, format, and characteristics of the data.
4. **Pipeline implementation:** Explain ingestion, storage, transformations, and output.
5. **Data quality:** Demonstrate how the pipeline handles invalid, duplicate, or missing records.
6. **Results:** Present the final analytical output and explain what it reveals.
7. **Challenges and lessons learned:** Discuss technical problems encountered and how you addressed them.

### Mandatory live demo

**Every presentation must incorporate a live demonstration of the actual data and working pipeline.**

The demonstration should include as many of the following as applicable:

- Showing the raw data in ADLS Gen2.
- Opening a Databricks notebook and executing a transformation.
- Displaying the resulting Silver or Gold dataset.
- Running a Spark SQL query or DataFrame aggregation.
- Showing the final analytical results.

A presentation consisting only of slides or screenshots will not satisfy the live demonstration requirement.

If a particular component cannot be run live because of a service restriction, explain the limitation and demonstrate the working components.

### Suggested presentation duration

Aim for **8–10 minutes per student**, including the live demonstration, followed by brief questions, subject to the final class schedule.
