## 6. Build Bronze and Silver for both station feeds

Bronze keeps the flattened source rows, including duplicates. Silver removes exact duplicate rows and adds readable timestamps. The observed data had no conflicting values for a station/snapshot key after exact deduplication; this approach assumes that remains true for the input being rebuilt.

```python
for feed in ["station_status", "station_information"]:
    raw_df = (
        spark.read
        .option("multiLine", "true")
        .option("recursiveFileLookup", "true")
        .json(landing_path + feed + "/")
    )

    flat_df = (
        raw_df
        .select("last_updated", "ttl", "version",
                F.explode("data.stations").alias("station"))
        .select("last_updated", "ttl", "version", "station.*")
    )

    (flat_df.write.format("delta").mode(write_mode)
     .saveAsTable(f"{catalog}.bronze.{feed}"))

    silver_df = (
        flat_df.distinct()
        .withColumn("snapshot_timestamp", F.timestamp_seconds("last_updated"))
    )
    if feed == "station_status":
        silver_df = silver_df.withColumn(
            "last_reported_timestamp", F.timestamp_seconds("last_reported")
        )

    (silver_df.write.format("delta").mode(write_mode)
     .saveAsTable(f"{catalog}.silver.{feed}"))
```

`explode` makes one row per station in each snapshot; `station.*` expands that station's fields into columns. Nested descriptive fields such as `eightd_station_services` remain nested. Only the two station feeds are transformed in this lab.

## 7. Build Gold `dim_station` with historical versions

Track changes in station name, coordinates, capacity, region, short name, and type. Keep the first observation and each subsequent attribute change, including changes back to an earlier combination. Compare values with NULL-safe equality.

```python
attributes = ["name", "lat", "lon", "capacity",
              "region_id", "short_name", "station_type"]
station_window = Window.partitionBy("station_id").orderBy("last_updated")

station_changes_df = (
    spark.table(f"{catalog}.silver.station_information")
    .withColumn("_attributes", F.struct(*attributes))
    .withColumn("_previous_attributes", F.lag("_attributes").over(station_window))
    .filter(
        F.col("_previous_attributes").isNull()
        | ~F.col("_attributes").eqNullSafe(F.col("_previous_attributes"))
    )
    .select("station_id", "snapshot_timestamp", *attributes)
)

version_window = Window.partitionBy("station_id").orderBy("valid_from")
dim_station_df = (
    station_changes_df
    .withColumnRenamed("snapshot_timestamp", "valid_from")
    .withColumn("valid_to", F.lead("valid_from").over(version_window))
    .withColumn("is_current", F.col("valid_to").isNull())
)

(dim_station_df.write.format("delta").mode(write_mode)
 .saveAsTable(f"{catalog}.gold.dim_station"))
```

The version key is **`station_id` + `valid_from`**. A version applies for **`valid_from ≤ snapshot_timestamp < valid_to`**; NULL `valid_to` marks the latest observed version. These boundaries record when the collected data first observed a change, not its guaranteed real-world change time.

## 8. Build Gold `dim_date`

Include every calendar day between the earliest and latest status snapshots, including dates without observations.

```python
status_df = spark.table(f"{catalog}.silver.station_status")
date_bounds_df = status_df.agg(
    F.min(F.to_date("snapshot_timestamp")).alias("start_date"),
    F.max(F.to_date("snapshot_timestamp")).alias("end_date")
)

dim_date_df = (
    date_bounds_df
    .select(F.explode(F.sequence("start_date", "end_date")).alias("calendar_date"))
    .withColumn("date_key", F.date_format("calendar_date", "yyyyMMdd").cast("int"))
    .withColumn("year", F.year("calendar_date"))
    .withColumn("month", F.month("calendar_date"))
    .withColumn("day_of_month", F.dayofmonth("calendar_date"))
    .select("date_key", "calendar_date", "year", "month", "day_of_month")
)

(dim_date_df.write.format("delta").mode(write_mode)
 .saveAsTable(f"{catalog}.gold.dim_date"))
```

## 9. Build Gold `fact_station_snapshot`

Keep one row per **`station_id` + `snapshot_timestamp`**, with bike/dock counts and service flags. Match each observation to the station version effective at that timestamp; joining on station ID alone would multiply historical rows.

```python
s = spark.table(f"{catalog}.silver.station_status").alias("s")
d = spark.table(f"{catalog}.gold.dim_station").alias("d")

fact_df = (
    s.join(
        d,
        (F.col("s.station_id") == F.col("d.station_id"))
        & (F.col("s.snapshot_timestamp") >= F.col("d.valid_from"))
        & (F.col("d.valid_to").isNull()
           | (F.col("s.snapshot_timestamp") < F.col("d.valid_to"))),
        "left"
    )
    .select(
        "s.*",
        F.col("d.valid_from").alias("station_valid_from"),
        F.date_format("s.snapshot_timestamp", "yyyyMMdd").cast("int").alias("date_key")
    )
)

(fact_df.write.format("delta").mode(write_mode)
 .saveAsTable(f"{catalog}.gold.fact_station_snapshot"))
```

Facts reference `dim_station` through **`station_id` + `station_valid_from`** and `dim_date` through **`date_key`**. The left join retains observations with no matching version; the completed lab had zero unmatched versions. These are logical relationships, not declared/enforced foreign-key constraints.

### 10.3 Understand MERGE with a tiny example

After the previous exercise, this source has one row for an existing item and one for a new item:

```sql
MERGE INTO <catalog>.<practice_schema>.delta_history_practice AS target
USING (SELECT * FROM VALUES (1, 6), (3, 4)
       AS incoming(item_id, quantity)) AS source
ON target.item_id = source.item_id
WHEN MATCHED THEN UPDATE SET target.quantity = source.quantity
WHEN NOT MATCHED THEN INSERT (item_id, quantity)
VALUES (source.item_id, source.quantity);
```

**Expected, not observed:** Item 1 becomes 6, item 2 stays 7, and item 3 is inserted with 4. This is an upsert: update matches and insert missing keys. A source containing conflicting matches must be resolved before MERGE. See [Delta MERGE](https://learn.microsoft.com/en-us/azure/databricks/delta/merge).

Before adapting MERGE, decide how to choose one source row per station and how to prevent a late older snapshot from replacing newer target data. Equal-timestamp conflicts also need a rule. Preserve observation history separately; this generic MERGE example does not implement those station rules.

### 10.5 Auto Loader: discover new files without rereading everything

A batch read lists the selected files again on each run. Auto Loader uses the `cloudFiles` streaming source and a persistent checkpoint to track ingestion progress. With the same valid checkpoint and Delta sink, a restarted ingestion can resume; this does not deduplicate the same business observation arriving in different files. It still needs your Silver rules. See [Auto Loader](https://learn.microsoft.com/en-us/azure/databricks/ingestion/cloud-object-storage/auto-loader/).
