### A. Azure Data Factory (10–15 minutes)

Read: [Microsoft Learn — Introduction to Azure Data Factory](https://learn.microsoft.com/en-us/azure/data-factory/introduction)

Understand the following concepts:

- **Pipelines:** How ADF organizes and orchestrates data workflows.
    - ADF (Azure Data Factory): creates links between resources and how to handle the results of files. So if a failure is returned you can handle that failure in the ADF with a retry, log, etc.

    **Addition:** Your failure-handling idea is right. A pipeline defines activities, their order, and success/failure dependencies. Retry policies and monitoring help operate those activities; linking resources alone does not define the workflow.

- **Activities:** What a Copy Activity does and how it differs from a transformation.
    - an activity is an individual action in an ADF. Copy is a predefined action that will import/copy data to a desired location

    **Addition:** Correct for this lab. Binary Copy transfers file bytes; it does not flatten station arrays or apply your Silver validation. Those transformations run in the notebook.

- **Linked Services:** How ADF connects to external systems such as AWS S3 and ADLS Gen2.
    - a linked service is like an SSH, you provide a handshake between two systems with the correct authn/authz and you can provide read-only, read-write, etc.

    **Correction:** Keep the connection-configuration idea, but SSH is a specific protocol that this copy does not require. Each linked service configures access to one system. Storage permissions are granted in that system; the Copy Activity uses source and sink datasets to connect the two sides. See [Section 2.2](2_Tue_Azure_Adv.md#22-linked-service-versus-dataset).

- **Datasets:** How datasets identify the files and data structures used by activities.
    - no idea, i know we set the type of data like binary and select a target, but not sure how all of it works.

    **Addition:** You already identified two key pieces: format and data selection. A dataset references a linked service and describes the data to use, such as bucket/container, directory, and Binary format. It is configuration rather than transferred data. Practice explaining which object changes when the directory changes but credentials stay the same.

- **Integration Runtime:** What executes ADF activities and transfers data.
    - is this just a compiler? I'm not following the question.

    **Correction:** A compiler translates code; Integration Runtime supplies execution/connectivity infrastructure for integration tasks. For Copy, it performs data movement; for a Databricks activity, it dispatches work to Databricks. Review the work-order example in [Section 2.3](2_Tue_Azure_Adv.md#23-integration-runtime), then explain who moves files and who runs Spark.

- **Managed Identities and RBAC:** How ADF authenticates to Azure Storage without storing account keys.
    - RBAC is role based credentials, so you can provide a permission to a role, then a resource can obtain that role to perform the provided permissions. Like a firefighter role can figth fires, John is given the role firefighter, John can now go fight fires.

    **Correction:** RBAC expands to role-based access control. Your analogy works when John is the identity, firefighter defines permissions, and the assignment includes a scope. A managed identity supplies the service identity and Azure-managed credentials; the role assignment supplies authorization. See [Section 3.1](2_Tue_Azure_Adv.md#31-why-a-managed-identity-helps).


Think about why we used ADF to transfer data from AWS S3 to Azure rather than writing a custom Python transfer script.
- ADF has a lot of built in features like activity copy, RBAC, etc. that reduce the complexity of a python script while also providing repeatability and log history

**Addition:** Your managed-features reasoning is sound. Connectors, monitoring, scheduling, and retries are useful examples. Azure RBAC is a wider Azure authorization system that ADF uses; a Python application can also use managed identity and role-based permissions. ADF reduces the workflow plumbing you would otherwise maintain.


### B. Azure Databricks and Apache Spark (10–15 minutes)

Read: [Microsoft Learn — What is Azure Databricks?](https://learn.microsoft.com/en-us/azure/databricks/introduction/)

Understand:

- What Databricks provides on top of Apache Spark.
    - spark is integrated into databricks, but we also have access to using SQL as well.

    **Correction:** Spark itself already supports SQL. Databricks adds a managed platform around analytics, including notebooks, compute management, workflows, and Unity Catalog integration. Compare the platform with the engine rather than treating SQL as the extra feature. See [Section 4](2_Tue_Azure_Adv.md#4-databricks-and-spark-how-the-notebook-executes).

- The difference between Spark DataFrames and ordinary Pandas DataFrames.
    - many differences, spark uses clustering (not on local), partitioning (parallelism), lazy processing, and more

    **Correction:** Partitioning and lazy transformations are good distinctions. Spark can also run locally on one machine; a cluster is a deployment choice, not a requirement for using its API. Partitions allow tasks to run in parallel when compute is available.

- What Spark drivers, executors, and clusters do.
    - drivers: organize and schedule the executors
    - executors: provided an amount of compute to process and hold data
    - clusters: divide up the work across machines (compute)

    **Addition:** Your driver/executor descriptions are broadly right. More precisely, a cluster supplies resources, its manager allocates resources, the driver schedules tasks, and executors run those tasks. A partition is a portion of the dataset. See [Spark cluster components](https://spark.apache.org/docs/latest/cluster-overview.html).

- Why Spark uses lazy evaluation.
    - to plan the most effective order of operation based on written code

    **Addition:** Correct direction. Transformations build a plan so Spark can optimize across operations before an action requests execution. For example, it may push a filter closer to a file read. It chooses a plan using available rules/statistics; this does not guarantee the globally fastest plan.

- What a Databricks notebook is and how it runs PySpark code.
    - like a jupiter notebook, allows you to break up code snipits into blocks that can be run independently. There is an engine underneath that runs the scripts

    **Correction:** The Jupyter comparison is useful. Cells can be executed separately, but their variables and outputs can depend on earlier cells in the same session. Attached compute executes code; a notebook is not itself the Spark engine.

- How Databricks reads data directly from ADLS Gen2.
    - because of ADF? like it uses RBAC?

    **Correction:** ADF already copied the files. The later notebook read uses Unity Catalog and the Access Connector storage identity to reach ADLS. It does not pass through ADF. Trace the separate requests in [Section 3.2](2_Tue_Azure_Adv.md#32-how-the-notebook-reaches-adls).


You should understand why Spark is useful for distributed data processing, even though our Citi Bike dataset is relatively small.
- as described above, spark can divide up the work across many machines, allowing for the ability to scale resources.

### Step 2 — Connect Databricks to ADLS Gen2

Using your Azure Databricks workspace:

1. Verify that Unity Catalog is available.
2. Configure or verify the Azure Databricks Access Connector.
3. Ensure its managed identity has the necessary storage permissions.
4. Create a Unity Catalog storage credential.
5. Create an external location pointing to your ADLS Gen2 container.
6. Create an external volume for accessing the source files.
7. Use a Databricks notebook to list and read the JSON files.

Example:

```

    "/Volumes/<catalog>/<schema>/<volume>/"
```

Then read an appropriate JSON directory:

```

    spark.read
    .option("multiLine", "true")
    .option("recursiveFileLookup", "true")
    .json("<your-source-path>")

df.printSchema()
display(df.limit(10))
```

Replace the placeholders with your own catalog, schema, volume, and source path.

### Step 3 — Create a Bronze Delta table

Use PySpark to read the source JSON files and write their contents to a Bronze Delta table.

For station-status data, flatten the nested station array into individual records.

Include useful metadata such as the source filename and ingestion timestamp.

Example Delta write:

```
bronze_df.write \
    .format("delta") \
    .mode("overwrite") \
    .option("overwriteSchema", "true") \
    .saveAsTable(
        "<catalog>.bronze.station_status"
    )
```

You may use the code demonstrated in class, adapting it to your own data.

**Expected result:** A Bronze Delta table visible in Databricks Catalog Explorer.

### Step 4 — Transform Bronze into Silver

Create a Silver table using PySpark transformations.

Your Silver processing should include:

- Casting important columns to appropriate data types.
- Removing records with missing station IDs.
- Filtering invalid values, such as negative bicycle counts.
- Deduplicating station observations using an appropriate station ID and timestamp combination.
- Converting timestamps into useful Spark timestamp columns.

Write the result as a Delta table.

**Expected result:** A cleaned Silver table containing valid station observations.

### Step 5 — Aggregate Silver into Gold

Create at least one Gold Delta table using the Silver data.

For example, calculate hourly bicycle availability across the network.

Your Gold table should include metrics such as:

- Hour of observation.
- Number of stations reporting.
- Total available bicycles.
- Total available docks.
- Average available bicycles per station.

If multiple snapshots exist for the same station during an hour, use the latest observation for that station in that hour before calculating network totals.

**Expected result:** A Gold Delta table containing hourly station availability metrics.

### Step 6 — Perform an analytical query

Write at least one SQL query against your Gold table.

For example:

```
SELECT *
FROM <catalog>.gold.hourly_network_availability
ORDER BY total_bikes_available ASC
LIMIT 5;
```

This identifies the hours with the lowest recorded bicycle availability, although the number of reporting stations should also be considered when interpreting the results.

Optionally, create a simple Databricks visualization showing bicycle availability over time.
