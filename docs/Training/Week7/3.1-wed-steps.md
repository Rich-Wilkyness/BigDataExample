## 3. Define Bronze ingestion

Add this to the pipeline source, changing the path only if your volume browser differs:

```python
from pyspark import pipelines as dp
from pyspark.sql import functions as F
from pyspark.sql.window import Window

SOURCE_PATH = (
    "/Volumes/richard_citibike_wg/default/"
    "richard_citibike_landing/citibike/station_status/"
)

@dp.table(name="bronze_station_status")
def bronze_station_status():
    return (
        spark.readStream
        .format("cloudFiles")
        .option("cloudFiles.format", "json")
        .option("multiLine", "true")
        .load(SOURCE_PATH)
        .select("*", F.col("_metadata.file_path").alias("source_file"))
        .withColumn("ingested_at", F.current_timestamp())
    )
```

This Bronze preserves the JSON envelope, including the station array. Tuesday's Bronze flattened that array immediately; this reconstruction delays flattening to Silver. Pipeline-managed Auto Loader manages schema/checkpoint locations, so do not add a manual `writeStream.start()` inside the definition. File-events provisioning remains unverified; this example does not enable managed file events.

## 4. Define Silver parsing and expectations

```python
@dp.materialized_view(name="silver_station_status")
@dp.expect_or_drop("station_id_present", "station_id IS NOT NULL AND station_id <> ''")
@dp.expect_or_drop("snapshot_present", "snapshot_timestamp IS NOT NULL")
@dp.expect_or_drop(
    "valid_counts",
    "num_bikes_available IS NOT NULL AND num_bikes_available >= 0 "
    "AND num_docks_available IS NOT NULL AND num_docks_available >= 0"
)
def silver_station_status():
    rows = (
        spark.read.table("bronze_station_status")
        .select(
            F.col("last_updated").try_cast("long").alias("snapshot_epoch"),
            F.explode("data.stations").alias("station")
        )
        .select("snapshot_epoch", "station.*")
    )
    return (
        rows.select(
            F.trim(F.col("station_id")).alias("station_id"),
            F.timestamp_seconds("snapshot_epoch").alias("snapshot_timestamp"),
            F.col("num_bikes_available").try_cast("int").alias("num_bikes_available"),
            F.col("num_docks_available").try_cast("int").alias("num_docks_available")
        )
        .distinct()
    )
```

`try_cast` produces NULL for invalid numeric values so the expectations can reject them. This requires a runtime supporting the DataFrame `try_cast` API. The output contract is deliberately limited to four columns. Exact duplicates disappear from that projected contract; conflicting values at the same station/timestamp remain a separate quality problem. Landing/Bronze retains the source information for investigation.

Set the pipeline's Spark configuration `spark.sql.session.timeZone` to `UTC` if exposed by your pipeline settings, or use its supported configuration mechanism. Confirm the effective time zone before interpreting hourly results. Do not assume a classroom browser's local time is the Spark session time zone.

## 5. Define hourly Gold

This reconstruction uses the latest observation per station within each hour, then sums availability across reporting stations. It is not a trip count. Valid input must have no conflicting values at a station/timestamp key.

```python
@dp.materialized_view(name="gold_hourly_availability")
def gold_hourly_availability():
    status = (
        spark.read.table("silver_station_status")
        .withColumn("snapshot_hour", F.date_trunc("hour", "snapshot_timestamp"))
    )
    latest = Window.partitionBy("station_id", "snapshot_hour").orderBy(
        F.col("snapshot_timestamp").desc()
    )
    return (
        status.withColumn("_rank", F.row_number().over(latest))
        .filter(F.col("_rank") == 1)
        .groupBy("snapshot_hour")
        .agg(
            F.countDistinct("station_id").alias("reporting_stations"),
            F.sum("num_bikes_available").alias("total_bikes_available"),
            F.avg("num_bikes_available").alias("avg_bikes_per_reporting_station")
        )
    )
```

The window's timestamp ordering does not resolve conflicting equal-timestamp observations. Treat the uniqueness check below as an acceptance requirement before using Gold. Production behavior should enforce an explicit rejection or source-precedence policy before publication.
