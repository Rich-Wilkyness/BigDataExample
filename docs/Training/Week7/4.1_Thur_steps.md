## 4. Demonstrate a keyed upsert

```sql
MERGE INTO richard_citibike_wg.week7_thursday_demo.delta_demo AS target
USING (
    SELECT 'ST001' AS station_id, 20 AS bikes_available
    UNION ALL
    SELECT 'ST003', 8
) AS source
ON target.station_id = source.station_id
WHEN MATCHED THEN
    UPDATE SET target.bikes_available = source.bikes_available
WHEN NOT MATCHED THEN
    INSERT (station_id, bikes_available)
    VALUES (source.station_id, source.bikes_available);

SELECT * FROM richard_citibike_wg.week7_thursday_demo.delta_demo
ORDER BY station_id;
```

**Expected:** ST001 = 20, ST002 = 15, ST003 = 8. Run the same MERGE again and inspect the same three logical rows. This demonstrates replay behavior for this deterministic, unique-key source and assignment update. It does not establish general MERGE idempotency or prevent duplicate keys in arbitrary input.

## 6. Start the stream and wait for completion

```python
bronze_stream = (
    spark.readStream
    .format("cloudFiles")
    .option("cloudFiles.format", "json")
    .option("cloudFiles.schemaLocation", SCHEMA_PATH)
    .option("multiLine", "true")
    .schema(snapshot_schema)
    .load(SOURCE_PATH)
    .select(
        F.col("last_updated"),
        F.explode("data.stations").alias("station"),
        F.col("_metadata.file_path").alias("source_file")
    )
    .select("last_updated", "station.*", "source_file")
)

query = (
    bronze_stream.writeStream
    .format("delta")
    .outputMode("append")
    .option("checkpointLocation", CHECKPOINT_PATH)
    .trigger(availableNow=True)
    .toTable(TARGET_TABLE)
)
query.awaitTermination()

print(spark.table(TARGET_TABLE).count())
display(spark.table(TARGET_TABLE).groupBy("source_file").count())
```

**Expected on fresh demo state:** Two station rows from one file. The corrected trigger syntax is `.trigger(availableNow=True)`; `availableNow::True` is invalid Python. `awaitTermination()` waits for this triggered query to finish before the next step reads its output.

Create a separate Python notebook, for example `citibike-mlflow-demo`. The following is an illustrative **MLflow 3** reconstruction; check the installed libraries and compatible compute first.

```python
import mlflow
import mlflow.sklearn
import sklearn

print("MLflow:", mlflow.__version__)
print("scikit-learn:", sklearn.__version__)

from pyspark.sql import functions as F

SILVER_TABLE = "richard_citibike_wg.silver.station_status"
spark.conf.set("spark.sql.session.timeZone", "UTC")
features_df = (
    spark.table(SILVER_TABLE)
    .select(
        "station_id", "snapshot_timestamp",
        F.hour("snapshot_timestamp").alias("hour"),
        F.dayofweek("snapshot_timestamp").alias("day_of_week"),
        F.col("num_bikes_available").cast("double").alias("num_bikes_available")
    )
    .dropna()
    .filter(F.col("num_bikes_available") >= 0)
)

pdf = (
    features_df.orderBy("snapshot_timestamp", "station_id")
    .limit(5000)
    .toPandas()
)

times = sorted(pdf["snapshot_timestamp"].unique())
if len(times) < 2:
    raise ValueError("Need at least two distinct observation times for a temporal split")
cutoff = times[max(1, min(len(times) - 1, int(len(times) * 0.8)))]
train_df = pdf[pdf["snapshot_timestamp"] < cutoff]
test_df = pdf[pdf["snapshot_timestamp"] >= cutoff]

FEATURES = ["station_id", "hour", "day_of_week"]
TARGET = "num_bikes_available"
x_train, y_train = train_df[FEATURES], train_df[TARGET]
x_test, y_test = test_df[FEATURES], test_df[TARGET]
```

This estimates the current observation's availability from station/time features. It does not implement a one-hour-ahead forecast, and the earliest 5,000 ordered rows may be unrepresentative. Keep the sample limitation and split boundary with any reported metric. Fit preprocessing on training data only. The bounded sample prevents collecting the entire Silver table into local Python memory.

## 10. Train and log one experiment run

Replace `<workspace-user>` with your Databricks workspace user path. If the instructor supplies an existing experiment, use that instead. For MLflow 2, consult the matching installed-version API; model logging can use `artifact_path` rather than MLflow 3's `name`.

```python
from sklearn.compose import ColumnTransformer
from sklearn.preprocessing import OneHotEncoder
from sklearn.pipeline import Pipeline
from sklearn.ensemble import RandomForestRegressor
from sklearn.metrics import mean_absolute_error, mean_squared_error
from mlflow.models import infer_signature

mlflow.set_tracking_uri("databricks")
mlflow.set_registry_uri("databricks-uc")
EXPERIMENT_PATH = "/Users/<workspace-user>/week7-citibike-demo"
mlflow.set_experiment(EXPERIMENT_PATH)

preprocessor = ColumnTransformer([
    ("station", OneHotEncoder(handle_unknown="ignore"), ["station_id"]),
    ("time", "passthrough", ["hour", "day_of_week"])
])
model = Pipeline([
    ("preprocessor", preprocessor),
    ("regressor", RandomForestRegressor(n_estimators=50, max_depth=8, random_state=42))
])

with mlflow.start_run(run_name="citibike-availability-demo") as run:
    mlflow.log_param("n_estimators", 50)
    mlflow.log_param("max_depth", 8)
    mlflow.log_param("source_table", SILVER_TABLE)
    mlflow.log_param("sample_limit", 5000)
    mlflow.log_param("split_cutoff", str(cutoff))
    model.fit(x_train, y_train)
    predictions = model.predict(x_test)
    mae = mean_absolute_error(y_test, predictions)
    rmse = mean_squared_error(y_test, predictions) ** 0.5
    mlflow.log_metric("mae", float(mae))
    mlflow.log_metric("rmse", float(rmse))
    signature = infer_signature(x_train, model.predict(x_train))
    model_info = mlflow.sklearn.log_model(
        sk_model=model,
        name="model",
        signature=signature,
        input_example=x_train.head(3)
    )
    run_id = run.info.run_id

print("Run ID:", run_id)
print("MAE:", mae, "RMSE:", rmse)
print("Model URI:", model_info.model_uri)
```

The corrected API names are `set_tracking_uri` and `set_registry_uri`, not `set_tracking_url` / `set_registry_url`. MAE/RMSE are regression metrics, not classification accuracy. No numeric result is claimed until this runs on the chosen sample.

In **Experiments**, open the experiment and run. Locate parameters, metrics, and the saved model. A second run with a different model configuration can be compared, but preserve the same evaluation population for a fair comparison.
