## Part 2 — Databricks Reading (15–20 Minutes)

Review the following topics using Databricks documentation or other reliable technical resources.

**1. Delta Lake**
- What is Delta Lake, and how does it differ from ordinary Parquet storage?
    - Delta Lake = warehouse for storing data. Uses blob storage with heirarchal namespaces
    - parquet = file type that uses metadata 
- What is Delta Lake Time Travel?
    - delta lake retains history with versions (much like git). This allows you to use time travel to view what a table looked like on a certain version or timestamp.
- What is the difference between `RESTORE`, `MERGE`, and `VACUUM`?
    - Restore = allows you to reset a table to a given version or timestamp
    - Merge = essentially an upsert. uses a target, source, and match condition.
    - Vacuum = removes files/rows from a table that don't match a defined output?

**2. Auto Loader**
- What problem does Auto Loader solve?
    - scheduling in databricks
- What is the purpose of `cloudFiles`?
    - it is how you declare an auto loader? 
- Why are checkpoints important for incremental ingestion?
    - checkpoints provide a replay spot for failed pipeline processes. These are points at which success has been measured.

**3. Lakeflow Jobs**
- What is a Databricks Job?
    - you can define a process and then connect jobs together. A good example is a bronze notebook job -> silver notebook job -> gold notebook job
- How do task dependencies work?
    - one task depends on another (essentially creating a step function of 1->2->3)
- What happens to downstream tasks when an upstream task fails?
    - downstream tasks depend on upstream tasks, if it fails then they stop and wait for the upstream to retry or get fixed to elicit a success
