## Part 1 — Azure Synapse Analytics: Reading Assignment

Today we explored Azure Synapse Analytics and how it can be used alongside Azure Databricks to build an end-to-end data engineering and analytics solution.

For this weekend, review the following concepts.

### 1. Introduction to Azure Synapse Analytics

Read about the purpose of Synapse and its major components:

- **Serverless SQL pools:** Query files stored in Azure Data Lake Storage without provisioning a traditional database server.
- **Dedicated SQL pools:** Provisioned data warehouse compute for larger, predictable analytical workloads.
- **Apache Spark pools:** Execute Python, PySpark, and Spark SQL for distributed data processing.
- **Synapse Studio:** A unified interface for developing SQL scripts, notebooks, pipelines, and analytical queries.

Reading: [What is Azure Synapse Analytics?](https://learn.microsoft.com/en-us/azure/synapse-analytics/overview-what-is)

### 2. Querying Data in Azure Data Lake Storage

Review how Synapse serverless SQL can query Parquet files directly from ADLS Gen2.

Focus on:

- The `OPENROWSET` function.
- Querying Parquet files without loading them into a traditional database.
- Creating SQL views over external datasets.
- Using SQL aggregations such as `COUNT`, `AVG`, `MIN`, `MAX`, and `GROUP BY`.
- Understanding how serverless SQL pricing depends on the amount of data processed.

Reading: [Query Parquet files using serverless SQL](https://learn.microsoft.com/en-us/azure/synapse-analytics/sql/query-parquet-files)

### 3. Data Quality and Analytical Views

Review the data-quality problem we encountered in today's Citi Bike demonstration.

Some stations consistently reported zero available bikes and zero available docks because they were not operational. We used the `is_installed`, `is_renting`, and `is_returning` fields to investigate their status.

Think about the difference between:

- **Silver data:** Cleaned, typed, validated records that preserve useful operational information.
- **Gold data:** Business-oriented datasets that apply analytical rules, aggregations, and filters.

Consider why we should generally preserve inactive station observations in Silver but exclude them from certain Gold availability calculations.

### 4. Apache Spark and Visual Analytics in Synapse

Review how Synapse notebooks can execute PySpark code using Apache Spark pools.

Focus on how Spark can read Parquet files, transform DataFrames, group and aggregate data, and produce analytical results.

Also review Synapse Studio's built-in charting capabilities for SQL query results and notebook outputs.

Reading: [Visualize data using Apache Spark in Synapse](https://learn.microsoft.com/en-us/azure/synapse-analytics/spark/apache-spark-data-visualization)

### 5. How Synapse and Databricks Work Together

Our Citi Bike project demonstrated an architecture in which Databricks prepares data and Synapse makes it available for SQL-based analytics.

**Architecture reviewed in class:**

```text
Citi Bike API
      |
      v
Azure Data Lake Storage
      |
      v
Bronze — Raw JSON
      |
      v
Azure Databricks
PySpark transformations and validation
      |
      v
Silver — Parquet in ADLS Gen2
      |
      v
Azure Synapse Analytics
Serverless SQL, views and aggregations
      |
      v
Gold Analytics / Reporting
      |
      v
Charts and Power BI
```

Consider these questions:

1. Why might an organization use Databricks for data engineering and Synapse serverless SQL for analytical consumption?
2. What advantages does Parquet offer compared with raw JSON for analytical queries?
3. When would you use a Synapse Spark pool instead of Databricks?
4. Why might a materialized Gold dataset perform better than a SQL view that repeatedly aggregates millions of Silver records?

You do not need to submit written answers. These questions are intended to help you review the material.
