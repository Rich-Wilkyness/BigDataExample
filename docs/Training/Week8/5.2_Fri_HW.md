## Part 1: Machine Learning Fundamentals

Review the following concepts:

- Regression: Predicting a continuous numerical value, such as a price, capacity, or demand level.
- Classification: Predicting a category, such as whether a transaction is fraudulent.
- Clustering: Grouping similar observations without predefined labels.
- Anomaly detection: Identifying unusual observations that differ from expected patterns.
- Forecasting: Predicting future values using historical data and time-related patterns.
- Reinforcement learning: Learning which actions produce the best outcomes through rewards and penalties.

Understand the difference between supervised and unsupervised learning, and why training and testing data should be separated.

## Part 2: Training and Evaluating Models

Review how scikit-learn can be used to train machine learning models.

Focus on these evaluation metrics:

- Accuracy: The proportion of predictions that are correct.
- Precision: Of the transactions predicted to be fraudulent, how many actually were fraudulent?
- Recall: Of all actual fraudulent transactions, how many did the model detect?
- F1-score: A metric that balances precision and recall.
- R² (R-squared): A regression metric describing how much of the variation in the target is explained by the model, relative to predicting the mean.
- Mean Absolute Error (MAE): The average absolute difference between predicted and actual numerical values.

Consider why accuracy alone may be misleading when fraud is relatively rare.

## Part 5: Generative AI and MLflow Traces

This is an important topic from today's class.

A trace is a structured record of what happens when an application processes a request.

For a generative AI application, a trace can capture:

- The input or prompt sent to the model.
- The model or API invoked.
- The response returned by the model.
- The time required to complete the request.
- Token usage, when available.
- Errors and the sequence of operations performed.

A trace can contain multiple spans. Each span represents an individual operation, such as retrieving data, constructing a prompt, calling an LLM, or processing its response.

For example, our fraud analysis application could produce a trace resembling:

- A user selects a suspicious transaction.
- The application retrieves the transaction features and fraud prediction.
- The application constructs a prompt for OpenAI.
- OpenAI generates an explanation.
- The application returns that explanation to the user.

### Why are traces useful?

Traces help developers understand application behavior, investigate errors, identify slow operations, monitor API usage, and inspect the information supplied to a generative AI model.

Important distinction: A trace shows the observable execution of an application. It does not necessarily reveal an AI model's private internal reasoning or complete chain of thought.

Also remember that tracing and evaluation are different. Tracing records what happened; evaluation determines whether the output was accurate, useful, and supported by the available evidence.
