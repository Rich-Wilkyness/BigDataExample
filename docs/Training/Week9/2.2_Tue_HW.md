## Part 2: ACID Transactions (10 minutes)

**Review the four ACID properties:**

- Atomicity: A transaction either commits completely or does not commit.
- Consistency: Transactions preserve defined database integrity rules.
- Isolation: Concurrent transactions interact according to defined isolation guarantees.
- Durability: Committed transactions survive failures covered by the system's durability guarantees.

Understand how ACID transactions work in traditional databases such as PostgreSQL and how table formats such as Iceberg provide transactional guarantees over data lake storage.

**Reading:**

- PostgreSQL — Transactions
- PostgreSQL — Transaction Isolation

Focus on the basic concepts rather than memorizing every isolation level.

## Part 6: The Rs of Data Engineering (5–8 minutes)

Review the following operational principles discussed in class:

| Principle | Main concept |
| --- | --- |
| Reliability | Consistent, correct pipeline execution |
| Resilience | Continuing or recovering when components fail |
| Recoverability | Restoring data and processing after failures |
| Reproducibility | Producing consistent results from the same inputs |
| Reusability | Sharing data and processing components |
| Responsiveness | Meeting data delivery and latency requirements |
| Robustness | Handling unexpected inputs and edge cases |
| Repeatability | Consistently executing processes |
| Reconciliation | Verifying data accuracy and completeness |

These are useful engineering principles rather than one universally standardized framework.

**Reading:**

- Google SRE Book — Addressing Cascading Failures
- AWS Well-Architected — Reliability Pillar

Skim the introductory material and focus on failure handling, recovery, and reliability rather than reading the entire documents.
